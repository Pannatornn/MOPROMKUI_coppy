# วิธีวัดสถานะ Emergency

เอกสารนี้อธิบายกลไกของ prototype และวิธีทดสอบทางวิศวกรรม ไม่ใช่การรับรองทางคลินิก

## ระบบตัดสินจากอะไร

1. ทุกข้อความของผู้ใช้ผ่าน `app/safety.py` ก่อนเรียก AI
2. กฎค้นหากลุ่มสัญญาณคุกคามชีวิต เช่น ไม่รู้สึกตัว/ไม่หายใจ หายใจลำบากรุนแรง เจ็บหน้าอกรุนแรง อาการโรคหลอดเลือดสมอง เลือดออกมาก ชักต่อเนื่อง แพ้รุนแรง สารพิษ อุบัติเหตุรุนแรง และเหตุอันตรายในการตั้งครรภ์
3. ระบบตรวจคำปฏิเสธ เช่น “ไม่มี”, “ไม่ได้”, “ปฏิเสธอาการ” เพื่อลด false positive
4. ถ้าพบ red flag จะตั้ง `emergency`, หยุดถาม และแสดงคำแนะนำให้โทร 1669 ทันที โดยไม่รอ AI
5. ถ้าไม่พบ red flag จึงเรียก AI เพื่อซักประวัติและเสนอระดับสำหรับบุคลากรตรวจ AI ไม่สามารถลดระดับ Emergency ที่กฎพบแล้ว

จำนวนคำถามจึงไม่ใช่ตัววัดความฉุกเฉิน เคส Emergency มีคำถามน้อยโดยตั้งใจ เพราะไม่ควรหน่วงเวลาการขอความช่วยเหลือ

## เกณฑ์อ้างอิง

ชุดกฎตั้งต้นจัดกลุ่มตามอาการฉุกเฉินวิกฤตของ UCEP/ระบบการแพทย์ฉุกเฉิน และข้อมูลรณรงค์ของกระทรวงสาธารณสุข เช่น หมดสติ ไม่หายใจ หายใจลำบากรุนแรง เจ็บหน้าอกรุนแรงเฉียบพลัน และอาการ FAST ของโรคหลอดเลือดสมอง อย่างไรก็ตาม ถ้อยคำจริงต้องให้แพทย์เวชศาสตร์ฉุกเฉินหรือพยาบาลคัดกรองของหน่วยนำร่องตรวจและอนุมัติก่อนใช้จริง

- สพฉ. เจ็บป่วยฉุกเฉิน โทร 1669: https://www.niems.go.th/1/News/Detail/6855?group=3
- เกณฑ์อาการฉุกเฉินวิกฤต UCEP: https://portal.info.go.th/universal-coverage-emergency-patients/
- กรมควบคุมโรค เรื่องอาการเจ็บแน่นหน้าอก: https://www.ddc.moph.go.th/dncd/news.php?deptcode=&news=37371
- กระทรวงสาธารณสุข เรื่องสัญญาณ Stroke และโทร 1669: https://pri.moph.go.th/news/news-info/news-release/2289-pr241068

## ชุดทดสอบและตัวเลขที่ต้องดู

ไฟล์ `tests/fixtures/triage_cases.json` เป็น regression corpus ที่มีประโยค Emergency และประโยคไม่ฉุกเฉิน รวมตัวอย่างคำพ้องและคำปฏิเสธ ใช้คำสั่ง:

```bash
docker compose exec -T app python scripts/evaluate_triage.py
```

รายงานจะแสดง:

- **Recall** = TP / (TP + FN): จากประโยค Emergency ระบบจับได้กี่เปอร์เซ็นต์
- **Precision** = TP / (TP + FP): สิ่งที่ระบบแจ้ง Emergency ถูกตามฉลากทดสอบกี่เปอร์เซ็นต์
- **False Negative (FN):** ประโยค Emergency ที่ระบบพลาด ต้องให้ความสำคัญสูงสุด
- **False Positive (FP):** ประโยคไม่ฉุกเฉินที่ถูกยกระดับผิด
- **Specificity** = TN / (TN + FP): ระบบปล่อยประโยคไม่ฉุกเฉินผ่านได้กี่เปอร์เซ็นต์

ผล 100% บน corpus นี้หมายถึง “กฎไม่ถอยหลังในตัวอย่างที่เก็บไว้” เท่านั้น ไม่ได้แปลว่าแม่น 100% ในผู้ป่วยจริง ก่อน pilot ต้องเพิ่มประโยคจากผู้เชี่ยวชาญ รวมคำผิด ภาษาพูด ภาษาถิ่น เด็ก ผู้สูงอายุ และการตั้งครรภ์ แล้ววัดแบบ blind test ที่แยกจากชุดพัฒนา

## ขั้นตอนเพิ่มตัวอย่างที่ระบบพลาด

1. ลบข้อมูลระบุตัวบุคคลและเก็บข้อความเป็นกรณีทดสอบ
2. ให้ผู้เชี่ยวชาญอย่างน้อยสองคนกำหนดฉลากและตกลงข้อขัดแย้ง
3. เพิ่มข้อความลง corpus โดยห้ามแก้ฉลากเพื่อให้เทสต์ผ่าน
4. ปรับกฎ ตรวจผล FN/FP ทั้งชุด และให้ผู้เชี่ยวชาญอนุมัติ
5. บันทึกเวอร์ชันกฎ วันที่ และผู้อนุมัติก่อน deploy
